• Não é de hoje que a experiência de usuário passou a ser
uma preocupação para as empresas que fornecem serviços web.
• No entanto, ainda existem usuários perdendo tempo esperando uma
página ser recarregada cada vez que uma nova informação é solicitada.
• Muitas vezes, essa lentidão ocorre porque a página requisitada é
recuperada do servidor e seu conteúdo é inteiramente carregado no
navegador.
• Uma solução para esse problema, bastante considerada atualmente no
desenvolvimento web, é utilizar o conceito de Single Page Application
(SPA), ou aplicação de página única.
Single Page Application
Single Page Application (SPA) é uma aplicação web que interage com o usuário atualizando
dinamicamente partes e dados da página, sem a necessidade de recarregar todo o conteúdo
durante seu uso, fazendo com que a aplicação responda de forma mais eficiente ao usuário.

-- 3 of 29 --

l.bertholdo@ifsp.edu.br
• O conceito de SPA foi lançado no início dos anos 2000
e propôs uma nova maneira de projetar páginas web.
• Em aplicações SPA, o conteúdo exibido no navegador não é uma página
HTML completa e estática, e sim partes do DOM (Document Object
Model) que vão se juntando para construir a interface da aplicação.
• Uma vez que a página inicial é carregada, todos os recursos necessários
para criar e exibir um novo conteúdo já estão na interface do usuário,
que é a responsável por controlar as transições dos conteúdos na página.
Single Page Application
Em uma SPA, toda nova atualização é processada localmente no navegador e anexada
dinamicamente ao DOM por meio de JavaScript, e, quando necessário, o servidor envia
apenas os dados brutos requisitados, geralmente em formato JSON. Isso torna o processo
de exibição da página mais rápido, pois o servidor passa a ter menos processos para
executar e há menos tráfego na rede ao realizar trocas de dados entre cliente e servidor.

Single Page Application
Diferentemente das aplicações web
tradicionais, que precisam renderizar todos
os elementos (barra de navegação, textos,
rodapés, anúncios etc) sempre que uma
página é solicitada, a SPA carrega o novo
conteúdo na página sem precisar
recarregar todos os seus outros elementos.
Isso é possível porque a camada de
apresentação do website é gerenciada pelo
navegador e não pelo servidor.

• Devido ao ganho de performance, com o tempo, as aplicações SPA se
tornaram cada vez mais populares. Para auxiliar na criação desse tipo de
aplicação, surgiram diversos frameworks baseados em JavaScript, entre
eles: o Backbone, o Angular, o Vue e o React.
Single Page Application
O Angular, lançado pelo Google em 2010, foi outro framework JavaScript pioneiro. Ele teve um
impacto significativo no cenário do desenvolvimento web, pois introduziu recursos inovadores, cujas
influências podem ser vistas nas bibliotecas que surgiram mais tarde, incluindo o React.
O Backbone, desenvolvido no início de 2010, foi uma das primeiras soluções para os problemas
existentes antes do surgimento do React, entre eles a reutilização de código e a testabilidade. Era uma
solução elegantemente simples: uma biblioteca que fornecia uma maneira de criar “modelos” e
“views”, a partir de uma abordagem própria do padrão de arquitetura MVC (Model View Controller).
O Vue, desenvolvido em 2014 durante um dos projetos do Google Creative Labs, permite criar
interfaces de usuário e aplicações web SPA. É considerado um framework “progressivo”, pois pode ser
utilizado em partes de uma aplicação existente ou para criar, do zero, uma aplicação completa.

• Atualmente, um dos frameworks mais populares usados para o
desenvolvimento de aplicações SPA é o React, também chamado de
React.js ou ReactJS.
• React é uma biblioteca JavaScript open source criada pelo Facebook
em 2013. É utilizada no desenvolvimento front-end para simplificar e
agilizar a tarefa de construção de interfaces de usuário interativas e de
alto desempenho.
• Atualmente, o React é mantido pela Meta, e também por uma enorme
comunidade de desenvolvedores pelo mundo. Sua documentação
oficial encontra-se no site https://react.dev/.
Framework React
Em 2015, o Facebook lançou também a biblioteca React Native, para criação de
aplicações móveis que utilizam as funcionalidades nativas das plataformas iOS e Android.

-- 7 of 29 --

l.bertholdo@ifsp.edu.br
• Usar o React para simplesmente criar e renderizar a marcação HTML
de uma SPA não é a principal vantagem desta biblioteca. O verdadeiro
ganho está no dinamismo e na performance da aplicação ao usá-la.
• Dada a natureza da JavaScript, qualquer modificação, por mais simples
que seja, propaga-se por toda a estrutura da árvore DOM, podendo
causar desde pequenas instabilidades até travamentos da página.
• Para entregar uma experiência de usuário melhor, criar aplicações de
alta performance e rápida renderização, o React foi projetado para
trabalhar com o DOM Virtual, uma abstração da árvore DOM.
Todas as atualizações na interface são aplicadas e processadas no
DOM Virtual e, apenas depois, são aplicadas em pontos específicos da
árvore DOM, sem interferir com o restante da árvore do documento.

• React usa uma sintaxe muito simples e clara denominada
JSX, uma extensão de sintaxe para JavaScript que simplifica a criação
de componentes e facilita a escrita de JavaScript.
• A JSX define cada componente como uma unidade independente e
mínima que compõe a interface. Isso acelera o processo de desenvol-
vimento e manutenção, pois os componentes gerados são reusáveis.
• Arquivos contendo sintaxe JSX devem ser gravados com extensão js,
ou, opcionalmente, jsx, pois são arquivos JavaScript.
JSX – JavaScript XML
React usa o transpiler Babel para fazer a “tradução” (transpilação) de JSX
para JavaScript, o qual já vem configurado e pronto para uso na biblioteca.

• Em JSX, todas as tags devem ser fechadas, ou com a tag de fechamento
tradicional (<div></div>, <p></p>), ou com a barra da tag de fechamento
automático (<div />, <p />), que inclui tags autofechadas (<br />, <img />).
• Nomes de atributos HTML devem seguir a sintaxe camelCase. Ex.:
colSpan, onClick, onSubmit.
• Além disso, os atributos HTML class e for devem ser escritos className
e htmlFor, pois todas as palavras reservadas da JavaScript têm sua
sintaxe modificada em JSX.
• Pode-se inserir qualquer expressão JavaScript na sintaxe JSX, desde que
seja envolvida por chaves. Ex.: { expressão JavaScript }.
JSX – JavaScript XML
A sintaxe JSX não aceita declarações JavaScript entre as chaves, somente
expressões. Expressões retornam um valor (por exemplo: x + 3) e
declarações executam uma ação (por exemplo: um bloco if-else).

DOM e React.DOM
O método creatElement do React, usado para criar marcação HTML, admite três parâmetros:
1) Elemento HTML a ser criado, 2) Objeto JavaScript que define um ou mais atributos para o
elemento {atributo1: "valor1", atributo2: "valor2", ...} e 3) Conteúdo do elemento.
Se não houver atributos a definir para o elemento, o 2º parâmetro deverá ser vazio {} ou null.
Já o 3º parâmetro poderá ser vazio, um conteúdo textual (nó de texto do elemento) ou até
mesmo outro elemento HTML criado usando a mesma sintaxe, resultando no aninhamento de
elementos em dois níveis, o que pode ser estendido a tantos níveis quanto forem necessários.
Note que foi usado className para definir o atributo HTML class, já que class é
uma palavra reservada da JavaScript. Ao criar a marcação HTML, o mecanismo
interno do React se encarrega de transformar className em class.

DOM e React.DOM
O método render do React destina-se a injetar no DOM a marcação HTML criada.
Ele admite dois parâmetros: 1) Marcação HTML (<h1> criado com o método

Usar JavaScript para criar e injetar marcação HTML no DOM é uma
tarefa possível desde os primórdios da linguagem. No entanto, React nos
fornece uma série de funcionalidades que simplificam esse trabalho.

• Na fase de montagem ocorre a renderização do componente. Os dois
métodos desta fase são usados com frequência:
• render(): Como vimos, esse método retorna um elemento React a ser
carregado pelo componente. Ele é chamado sempre que o componente
é carregado para renderização ou quando há alguma atualização.
• componentDidMount(): Esse método é chamado imediatamente após
o método render(), ou seja, logo após ter ocorrido a renderização do
componente.
Mounting
A chamada do método componentDidMount() é o momento ideal para execução de
scripts que bloqueiam a renderização da página, pois, como a página já está renderizada,
este bloqueio não ocorre. O exemplo clássico de uso desse método é para chamadas a
APIs que retornam dados, as quais podem bloquear a renderização.

Atualização de Dados com state
Em JavaScript, state é um termo genérico para designar um objeto
destinado a armazenar dados passíveis de serem modificados.

-- 7 of 20 --

l.bertholdo@ifsp.edu.br
• Em React, cada componente possui e gerencia o seu próprio objeto
state, ao contrário da maioria dos frameworks JavaScript que definem
um objeto state global para toda a aplicação.
• O único componente que pode alterar o objeto state é aquele no qual
o state foi definido, ou seja, o componente “dono” do state. Tentar
alterar o state de um componente a partir de outro componente (seja
pai ou filho) resulta em erro.
• Ao atualizar os dados no seu state, um componente-pai pode passá-los
para seus componentes-filhos por meio do objeto props. Com isso,
uma atualização no componente-pai pode ser refletida em todos os
seus componentes-filhos.
